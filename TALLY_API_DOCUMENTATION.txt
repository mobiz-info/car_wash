1. GENERAL OVERVIEW & AUTHENTICATION
================================================================================
All endpoints return standard application/json responses.
No Authorization header (Bearer token) or session cookie is required.
To isolate data between different corporate accounts / tenants, every request
must specify which company's records are being queried via the "client_id" query
parameter.

================================================================================
2. RESOLVING client_id
================================================================================
The "client_id" parameter can be:
  a) The exact UUID of the Client / Company
     Example: ?client_id=bf1345a8-777b-4ad0-9753-764ec6dd42cb

  b) The Company Name (case-insensitive, exact or partial match)
     Example: ?client_id=Mobiz%20Technologies
     Example: ?client_id=Koda%20Car%20Spa

Alternatively, "company_id" or "company_name" can also be used as query parameter
names.

================================================================================
3. ERROR CODES & FORMAT
================================================================================
If client_id is missing:
  HTTP Status: 400 Bad Request
  {
    "status": "error",
    "message": "client_id is required"
  }

If client_id does not match any active company:
  HTTP Status: 404 Not Found
  {
    "status": "error",
    "message": "Company not found with client_id: <value>"
  }

If an invalid HTTP method is used (e.g. POST):
  HTTP Status: 405 Method Not Allowed
  {
    "status": "error",
    "message": "Only GET method is allowed"
  }

1. LEDGER CREATION (Debtors):

     <LEDGER NAME="Anshid" ACTION="Create">
       <PARENT>Sundry Debtors</PARENT>
       <OPENINGBALANCE>0</OPENINGBALANCE>
     </LEDGER>
   </TALLYMESSAGE>

     <ALLLEDGERENTRIES.LIST>
